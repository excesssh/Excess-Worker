# Platform status

Code paths are not a support claim. The Linux and Windows controller boundaries have passed their documented native fixtures. Both source64 local closed packages completed real isolated CPU jobs with pairing, draining and device revocation against an ephemeral fixture coordinator and synthetic PGlite ledger. See the [exact package report](verification/packaged-cpu-source64.json). Positive installation, production signed updates, trusted Windows signing, public production service and GPU execution remain unverified for release.

| Area | Evidence | Status |
| --- | --- | --- |
| Linux controller boundary | Linux x64 fixtures verify private mount/PID/network namespaces, read-only app/model/state views and broker-mediated state writes, absent host paths/processes, direct-network denial, peer authentication, broker restrictions, cleanup and stop reaping. A bounded cgroup v2 service is required by the production entry. | Source/kernel fixture evidence; the package manifest still marks the controller unverified and closed. |
| Linux CPU job | Qwen3-4B Q4_K_M through llama.cpp on CPU, two threads and an 8 GiB configured memory cap. A local fixture HTTPS coordinator and test-only PGlite database used a synthetic ledger. Pairing, a three-token result/receipt, draining, clean exit, host-lock release and revocation passed; model bytes were unchanged. | Local integration evidence only. No chain backing, paid demand, public coordinator, real payment or downloadable install. See the [packaged report](verification/packaged-cpu-source64.json) and [earlier integration report](verification/linux-controller-cpu.json). |
| Linux model paths | Selected model/runtime trees are mounted read-only by descriptor. The controller exposes only `ai/models`, `ai/runtimes` and optional `ai/sd-runtimes`; unrelated store siblings are not mounted. | Local ext4/DrvFS and hostile fixture evidence; no general filesystem compatibility claim. |
| Linux resources | The controller fails closed without a dedicated `excess-worker.service` cgroup v2 boundary. Its policy requires swap 0, at most 128 tasks, at most 200% CPU and memory no higher than 12 GiB. Scratch is a 256 MiB tmpfs. | Kernel/package fixtures and local user-cgroup proof; no published installation/bootstrap. |
| Windows x64 controller | The source includes a pinned AppContainer controller, typed host broker and separate runtime sandbox. The Linux device signing key remains read-only inside its confined controller; on Windows the device signing key stays in the trusted host outside the AppContainer. Controller and sandbox native fixtures passed 3/3 with zero skips or failures when run with the documented neutral roots and pinned toolchain. The source64 package also completed real CPU inference, pairing, draining, reap/cleanup and revocation with unchanged package bytes. | Scoped local package execution and native fixture evidence; positive installation and production updates remain unverified. |
| Windows signed update reporting | The host captures the paired origin and current signed package release, calls the existing signed release checker and returns a bounded, validated status through a fixed no-payload RPC. The child cannot choose an origin, version, URL or installer command. Automatic installation is disabled; manual signed host-side CLI updating remains. | Reporting is implemented in source. A production signed update exchange and updated package installation have not been verified. |
| GPU | No GPU execution has been verified on either platform. The source's CUDA/Vulkan selections are implementation choices. | Unverified. Do not claim GPU support. |
| Install, update and release | Installer scripts verify local metadata and archives but intentionally refuse installation while bootstrap and safety gates are closed. No release has been published. Windows automatic installation is disabled; production signed-update behavior remains unverified. | Closed. |

The local CPU report is not evidence of a live coordinator, funded demand, an external production database, real payments or a public binary. Fixture jobs and synthetic accounting stay separate from production evidence. A health probe or inventory listing is not proof of inference.

Before widening support, run the exact signed package through bootstrap, installation, restart, update, rollback, drain and revocation on clean supported hosts. Verify actual outputs and clean shutdown with each claimed backend. Keep CPU, GPU, fixture and external-service evidence separate.
